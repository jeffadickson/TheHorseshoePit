    • BENCH-001
    1. Provenance BENCH-001

    Download a public-domain network corpus and retain its SHA-256 and source URL. Use deterministic ASCII/LF derivatives of approximately 1, 8 and 32 MiB.
    BENCH-002
    2. Equivalent implementations BENCH-002

    Compare eight documented operations using GNU utilities, idiomatic PowerShell pipelines and PowerShell StreamReader loops. Validate output length and SHA-256 against an independent reference for every run.
    BENCH-003
    3. Repeatable timing BENCH-003

    Run sequentially with one warmup and seven measured repeats per cell, seeded random order and process-startup-inclusive wall time. Retain raw measurements and report medians and dispersion.
    BENCH-004
    4. Verification evidence BENCH-004

    Run edge cases, reproducible randomized equivalence checks, negative cases and deliberate worker mutations. Collect line and branch coverage where tooling supports it and disclose gaps.
    BENCH-005
    5. Installed ripgrep comparison BENCH-005

    Install BurntSushi.ripgrep.MSVC with winget. Compare four equivalent search operations against contemporaneous GNU grep, interleaving sequential runs across all three existing inputs with one warmup and seven measured repetitions. Record the installed executable version, path and SHA-256, verify outputs, and retain seeded fuzz, negative, mutation and coverage evidence.
    BENCH-006
    6. Small-file latency BENCH-006

    Compare literal search, regex search and matching-line counts on contiguous corpus slices near 1 KiB and 64 KiB using ripgrep, GNU grep, PowerShell pipeline, PowerShell reader and Select-String. Interleave all five engines, include process startup, verify every output, and retain seven measured repetitions plus one warmup per cell. Verify fixed and seeded randomized fixtures and record input provenance, match counts and coverage limitations.
    BENCH-007
    7. Both rawk implementations BENCH-007

    Build stefanalfbo/rawk and quinnjr/rawk (awk-rs) from unmodified pinned commits in release mode with locked dependencies. Compare identical field extraction, word count and line count programs against contemporaneous GNU awk at all five existing file sizes, with sequential interleaved order, one warmup and seven measured repetitions. Verify each output against an independent reference; retain compiler, source and executable provenance, bounded fuzz, malformed-input, negative, mutation and coverage evidence.
    BENCH-008
    8. Long-field scanner correctness BENCH-008

    Retain the original frawk long-field compatibility failure. Diagnose buffer-growth state handling, provide a separate minimal source fix, and verify boundary and seeded randomized cases against independent expected output. Record targeted test, negative-control and coverage evidence; patched results must not silently replace historical benchmark results.
    BENCH-009
    9. Tuned GNU tools as user defaults BENCH-009

    Build GNU awk with -O3 -march=native -mtune=native -ftree-vectorize. Retain compiler flags and upstream test logs. Install the tuned GNU awk and grep in a separate user directory with their runtime dependencies. Verify deterministic long-field and randomized outputs against existing GNU references, reject malformed programs, and detect a deliberate output mutation before prepending the installation directory to the user PATH. Preserve the previous user PATH for rollback and disclose test coverage limitations.
    BENCH-010
    10. Sed implementations and replacement alternatives BENCH-010

    Compare GNU sed, BusyBox sed, uutils/sed and red on six equivalent operations across the existing five corpus sizes. Compare sd only for literal and numeric-regex replacements using non-mutating preview mode. Deduplicate byte-identical GNU binaries. Qualify each corpus cell, use one warmup and seven seeded shuffled sequential repeats, verify every timed output by length and SHA-256, and preserve input hashes. Retain edge/binary compatibility failures separately from passes. Record pinned acquisitions, independent oracle tests, seeded random cases, malformed input, command and Stryker.NET source mutations, line/branch coverage and tooling limitations. Add results to the existing report without combining historical sessions.
    BENCH-011
    11. Offline experimental overview BENCH-011

    Generate a self-contained responsive HTML overview of the methodology, nine experimental cohorts, findings, verification failures and limitations. Embed all 427 seven-repeat summaries (2,989 measured commands and 427 warmups). Restrict interactive rankings to original cohorts, show median/quartiles/observed ranges, and avoid throughput claims for early-exit workloads. Validate data completeness and units, malformed input, deterministic native/managed generation, seeded properties and source/client mutations. Record coverage scopes and disclose the lack of rendered visual verification when browser policy prevents preview. Retain generator/template sources and publish the overview with the existing repository.
    BENCH-012
    12. Diff implementations, algorithms and compiler tuning BENCH-012

    Compare GNU diff default/minimal/speed-large-files, same-source generic/native GNU and Rust uutils builds, official uutils, BusyBox and Git Myers/minimal/patience/histogram. Use deterministic book and source-code fixtures with identical, scattered, inserted/deleted, moved, repetitive, different and long-line content. Record actual byte sizes and hashes. Qualify each cell by applying its unified patch independently and comparing reconstructed bytes exactly; repeat verification for every timed sample. Retain edge/binary failures and timeout exclusions separately. Run sequential shuffled fresh processes with one warmup and seven measured repetitions, recording wall time, CPU time, process peak working set and patch/edit sizes. Separate compiler experiments from distribution comparisons. Retain bounded independent minimality checks, negative tests, seeded property tests, source/patch mutations, coverage scopes, pinned acquisitions, reproduction commands and an offline HTML report without altering historical cohorts.
    BENCH-013
    13. Test methods inside the HTML reports BENCH-013

    Document workload semantics, concrete command arguments, input construction, environment controls, stopwatch inclusion/exclusion, warmups, repeat ordering, correctness gates, statistics, failure/resource policies and verification limitations directly in the overview and diff HTML reports. Make ripgrep's measured scope and flags explicit. Distinguish search hashing inside its clock from diff hashing and patch application outside its clock. Preserve all recorded timing data. Verify required methodology text, evidence links including cross-document fragments, and report generation without rerunning measurements.
