How to read these results

Lowest median comes first within each fixture and size. Elapsed time includes fresh process startup and raw stdout capture; input preparation, patch hashing and GNU patch application occur outside the clock. Warm filesystem cache, one warmup and seven sequential shuffled rounds; seed 20261027. Min–max is an observed range, not a confidence interval. Memory is the median OS peak working set of the diff process, not allocations or total process-tree memory.

All commands emit unified patches with three context lines. Git indentation heuristics, external diff, text conversion, color, renames and user/system configuration are disabled. GNU uses binary I/O and text mode; other implementations may reject binary fixtures. Different headers contribute to patch byte counts. Added+deleted lines measure edit size, not human readability. Minimality is independently checked only on bounded LF-terminated random fixtures. Source code is synthetic repetition of the retained harness snapshot; the book inputs derive from the existing public-domain corpus.

The compiler experiments compare the same source and toolchain within each language: GNU generic -O2 against -O3/-march=native/-mtune=native/-ftree-vectorize; Rust release generic against target-cpu=native (both inherit thin LTO and one codegen unit). Installed/release binaries are separate baselines, not controlled compiler comparisons. No global fastest-tool claim follows from this host.
