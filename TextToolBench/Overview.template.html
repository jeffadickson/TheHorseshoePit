01 / The findings

No single tool wins everything.

These are workload-specific observations on one Windows machine. Comparisons stay inside their original sessions.

SEARCH / GREP

ripgrep led the direct comparison.

At 32 MiB, it had the lower median in all four search workloads against the interleaved GNU grep control.

FIELDS / AWK

frawk and mawk split the honors.

In the mawk/frawk/GNU cohort, frawk led large-file field extraction and word counting. mawk led line counting and both small-file sizes.

Correctness matters.

02 / Experimental design

Same bytes. Explicit boundaries.

The stopwatch measures the whole command, including process startup, output transfer and hashing—not just a scanning loop.

01 · Acquire

Download the public-domain War and Peace text; retain source URL and SHA-256.

02 · Derive

Deterministic ASCII/LF slices and repeated text near five target sizes.

03 · Verify

Independent references, edge cases, random inputs and negative controls.

04 · Interleave

Sequential fresh processes in seeded shuffled order; one warmup per cell.

05 · Summarize

Seven measured repeats. Medians, quartiles and observed min–max ranges.

What qualifies as a result?

  • Exact outputMatching byte count and SHA-256 before a sample is retained
  • Text contractCase-sensitive ASCII and LF for timed corpora; no newline normalization
  • Failure policyCompatibility failures are recorded, never silently counted as passes
  • ProvenanceExecutable hashes, versions, source revisions, flags and raw JSONL
  • ExclusionsNo successful frawk JIT timings; no timings of the patched frawk or tuned awk

05 / Following the causes

What changed the results?

Controlled variants help explain performance. They do not turn a single benchmark into a general claim about a language.

Compiler experiment / GNU grep

Native tuning helped, modestly.

Same grep source, GCC 16.2.0, runtime and configuration. Generic O2 versus -O3 -march=native -mtune=native -ftree-vectorize.

2–8%

Lower 32 MiB medians across four workloads. GCC reported 32-byte vectorization in DFA code; that alone does not establish where runtime was spent.

The installed reference uses a different compiler/runtime. Neither this session nor native awk validation includes a fresh ripgrep comparison. Build experiment evidence ↗
Profiling experiment / Rust AWKs

Output buffering was consequential.

Wall-clock stack sampling pointed to frequent output writes. Separate variants added a 64 KiB BufWriter, with fresh controls measured in the same session.

4.96× / 1.54×

Original / buffered time for 32 MiB field extraction: quinnjr/awk-rs and stefanalfbo/rawk, respectively.

This was wall-clock sampling, not ETW CPU accounting or allocation profiling. Counting operations still exposed field-copying costs. Profile and patch evidence ↗
06 / Qualification, not just speed

Keep the failures visible.

Coverage scopes differ. A high percentage is evidence of execution, not proof of correctness or universal compatibility.

  • PASS
    All retained timed outputs matched.

    __MEASURED__ commands verified against their references. Warmups, profiling and bug probes are separate observations.

  • FIX
    frawk lost the first field on buffer growth.

    A retained prefix was rescanned with the previous scan's tail state. The separate patch restores the initial state: 96 boundary checks and 144 seeded property checks pass. One targeted nextest test passed; 284 unrelated tests were skipped. Bug report · Patch.

  • FAIL
    Seven sed edge failures remain failures.

    BusyBox/red missing-final-newline behavior and BusyBox binary-input behavior differ from the reference. The timed ASCII/LF inputs still qualify. Sed qualification details.

  • GAP
    Native awk installation has qualified upstream tests.

    Its initial regex crash required 128-bit vectors in one source file. The final build passed 338 output checks and extension loading; two PTY cases remain unverified in this noninteractive host. A timeout case passed serially. Installation evidence.

07 / Reading this responsibly

The limits are part of the result.

  • One host and one underlying book. Pattern density, encoding, file layout, regex features, storage and operating system can change the outcome.
  • Warm-cache, fresh-process wall time includes startup and SHA-256 output handling. Large output volumes add transfer and hashing cost.
  • Seven samples per cell are descriptive. Wide or overlapping ranges weaken fine-grained rankings; the whiskers are not confidence intervals.
  • Inputs are synthetic scaling derivatives. Small-file startup results do not predict large repository searches or parallel directory traversal.
  • Official distributions use different compilers, runtimes and release flags. Language alone does not explain a performance result.
  • Prefix selection stops after 100 records. Whole-file MiB/s would be misleading and is intentionally omitted for that workload.
  • Compatibility failures cannot be averaged away. frawk's patch and the tuned awk installation are verified separately and were not retimed here.
  • Raw records and cohort boundaries are retained. Historical results are not silently relabeled after a tool is upgraded or installed as a default.
